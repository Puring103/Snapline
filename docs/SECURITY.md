# Snapline 安全模型

## 信任边界

- Windows 客户端是内容明文、用户主密钥和 AI Key 的唯一信任端。
- Snapline 服务端负责认证、密文同步和密文附件存储，不持有内容解密密钥。
- 用户配置的 OpenAI 兼容服务会接收用户主动送入模型的解密内容；该边界必须在设置界面明确展示。

## 密钥层次

注册时客户端生成随机 256 位 UMK 和恢复密钥。密码通过 Argon2id 派生 KEK，KEK 只包装 UMK；恢复密钥独立包装同一 UMK。每条记录和每个附件使用随机 DEK，DEK 再由 UMK 包装。记录、附件和包装密钥均使用 XChaCha20-Poly1305，并将对象 UUID 绑定为附加认证数据，阻止密文跨对象替换。

附件采用 1 MiB 分块格式，每块使用随机 128 位 nonce 前缀和单调 64 位分块计数构成 192 位 nonce。每块附加认证数据包含对象 UUID、分块序号和结束标记；解密拒绝篡改、截断、追加内容和错误对象。

## 本地存储

- UMK 只驻留于已解锁 Tauri 进程内存，结构释放时显式零化。
- Refresh Token 和后续 AI API Key 写入 Windows Credential Manager。
- SQLite 只保存加密记录信封、非敏感同步状态和加密附件头；标题、Markdown、标签、特殊标记、AI 元数据和附件原文不以明文落盘。
- 附件直接从输入流写入加密临时文件，完成同步和校验后原子移动为正式对象，Snapline 不创建自己的明文中间文件。
- AI Base URL、模型和 API Key 作为单个凭据写入当前用户的 Windows Credential Manager；读取配置的前端命令只返回 Base URL、模型和状态，永不返回 API Key。
- AI 元数据随记录内容使用记录 DEK 加密。FTS5 索引只存在于已解锁进程的内存 SQLite 中，登录后从解密元数据重建，数据库文件不保存标题、转写、摘要或搜索文本。
- 视频处理使用固定的 FFmpeg 8.1.2 Windows 构建。首次使用时从固定 HTTPS URL 下载并验证固定 SHA-256；视频密文直接流入 FFmpeg stdin，关键帧和压缩音轨从 stdout 进入模型请求，不创建明文源视频。

## AI 服务边界

配置保存前，客户端使用最小 PNG、WAV 和严格 JSON Schema 请求验证用户指定模型。远程 Base URL 必须使用 HTTPS；仅回环地址允许 HTTP。模型请求直接从 Windows 客户端发出，Snapline API、PostgreSQL 和同步信封均不包含 AI Key。

记录正文和附件中的指令按不可信数据处理。元数据请求使用独立系统指令，并对模型返回结果执行字段集合、类型、长度和数量限制。无 AI 配置、Key 失效或模型服务离线时，记录、加密附件、自动保存和云同步不受影响；处理作业保留并按错误类别退避重试。

Agent 只能访问当前已解锁账户的七个白名单只读工具，不能执行模型生成的 SQL、命令或文件路径。工具结果明确标记为不可信数据；工具轮数、单轮调用数、结果数、单条正文和总上下文均有硬上限。客户端引用列表由工具实际返回且已交给模型的记录 ID 生成，不接受模型伪造的引用。搜索仅使用内存 FTS5 和结构化过滤，不使用 Embedding 或持久化明文索引。

## 服务端与网络

密码使用 Argon2id 哈希；Refresh Token 在 PostgreSQL 中只保存 SHA-256 哈希并在刷新时轮换。所有资源访问同时约束已认证用户和设备，撤销设备会使现有会话失效。

端到端加密不替代 TLS。当前 `http://122.51.119.75/snapline/` 只允许开发验证；明文 HTTP 会暴露密码和 Token。正式账号、真实内容和 AI Key 使用前必须配置域名、可信证书及 HTTPS，并将 HTTP 重定向到 HTTPS。

## 恢复与限制

恢复密钥只在注册完成时展示一次。用户同时遗失密码和恢复密钥后，服务端无法恢复内容。服务器被攻破可能导致密文删除、回滚或流量分析，但不应直接泄露记录内容；客户端仍必须通过版本、游标和 AEAD 校验拒绝篡改数据。
